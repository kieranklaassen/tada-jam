---
title: The core touch of a game is fun with no goal, and it is built and judged before any goal, challenge or content is added
applies_when:
  - designing a new game for the jam
  - choosing the main action a child performs in a game
  - turning a lab demo into a real game
  - adding goals, puzzles or levels to a game whose basic action is not yet fun
tags: [core-action, toy, prototype, depth, replay]
---

The first thing built is the one action the child's finger performs most, in an otherwise empty scene, with its sound and motion. It stays in the plan only if doing it again and again is a pleasure with nothing to achieve. Goals, challenges and content are added to an action that already passes.

Do:

- The action is pleasant alone in an empty scene, with no goal.
- Random tapping always produces something pleasing and never a punishment.
- A person watching can tell within about three seconds what the child is doing.
- The simplest use always works, so no child is stuck, and the controls need no thought.

Do not:

- A goal, a story or a look does not make up for a dull action.
- A design built around a score does not become a toy when the score is deleted. The interest was in the pressure.

Exception: none. In a learning game the core action is also the school skill (`the-mechanic-is-the-school-skill.md`).

Evidence: Gabler and Gray's first rule of prototyping is to build the toy first, and they warn that heavy theming does not save a bad design [V]. Miyamoto and Iwata say the same of Mario 64 [V]. The point about score-driven designs is inference [I]. The local case is the lab's first round of 30 goal-first prototypes, none of which the owner liked (`lab/arcade/RESEARCH.md`).
